# 国宝详情正文写作规范（给写手 agent）

你在给「195 件永久禁止出境文物」App 写详情页正文。读者已经知道这件文物叫什么、在哪家馆，
他们点进来想看的是：它到底是什么来路、为什么重要、凭什么不可替代、为什么国家不让它出国。

## 产出一个 JSON 文件

路径固定：`.drafts/details/<你的批次名>.json`，结构：

```json
{"3": "## 它的前世今生\n\n正文……", "4": "## 它的前世今生\n\n……"}
```

key 是文物 id（字符串），value 是 `detail` 字段的完整 markdown 长文。

## 格式（App 端只实现这个子集，多写不会渲染）

- 只有 `##` 二级小标题。不要 H1、不要 `###`（除非确有小节）。
- 段落之间空一行。`-` 无序列表、`1.` 有序列表。`**粗体**`、`*斜体*`。
- **不支持**：表格、引用块（`>`）、链接、图片、代码块、分割线（`---`）、`~~删除线~~`。
- 正文里不写 HTML 标签，不写「点击查看更多」这类界面文案。

## 结构：四段是**示例**，不是模板

上面四句只是「这类内容通常长什么样」的举例。**不要为了凑格式硬写一节。**

真实原则只有一条：**这件文物有什么值得说的，就说什么；没什么值得说的，跳过。**

- 一件陶器如果它的价值全在造型工艺上，「前世今生」和「不可替代」可以合并讲，不必单独开一节。
- 一件玉器的「为什么不能出国」如果就是「易损有机质 / 孤品」，一句话说完即可，不用复述法律条文。
- 反过来，如果它背后有一段惊心动魄的流转史（比如抗战藏宝、近代劫难），那一段值得单独展开，比其他三节都长。
- 一篇文章有 2–5 节都可以。标题自然写，不要求出现「前世今生」「不可替代」这些字眼。

**判据**：写完之后，检查每一节，问自己「删掉这一节，读者会损失什么？」如果答不上来，就删掉。同样的话不写第二遍。

## 硬规则

- 200–2400 字（去标记后的中文字数，含小标题）。**别为凑字数注水**，200 字能讲清的就 200 字，
  讲不透再补，上限 2400。宁短勿冗——一件小器物 300 字写透，比 1200 字车轱辘话强。
- 并列的物证、数据、时间节点用 `-` 列表排，读得快。一件都没有也行，别硬凑。
- 只要正文里提到「为什么不能出国」这件事（无论哪一节），必须出现「出境」和「禁止」两个词——
  因为要讲的是机制，不是感叹。如果这件文物的篇幅里根本没写这部分，则不检查。
- 年份写全：古代写「公元前 221 年」，近现代写「1939 年」。**不要写「221 年」「1023 年」这种**（校验器会判错：四位数且不在 1900–2099 之间的一律要求带「公元/公元前」）。
- **有争议的说法必须标出来源或分歧**（年代、释读、产地、真伪），不要单向陈述。写「学界多认为……也有学者主张……」。
- **不确定的事不写**。宁可少一段，不编一个数字。没有来源的尺寸、重量、价格，删掉。
- 不要把 item 里的 `story` / `reason` 原文贴进来。它是素材，不是定稿，要重写、扩写。

## 「为什么不能出国」怎么写（按需，只在值得写时写）

这一节最容易写成空话，也最容易写重复。**195 件都是同一套法律、同一个目录、同一条审批流程**——
如果每件都把三段法条复述一遍，读者读十件就烦了。

所以：

- **机制只讲这件用得上的那一层**。第一批的那件讲「2002 年首批目录的来历」就够；
  第三批的书画讲「2012 年第二批为什么单独为书画设一批」才有信息量。
- **法条一句带过**：「国务院分三批公布《禁止出境展览文物目录》（2002 年 64 件、2012 年 37 件、2013 年 94 件），
  列入即禁止出境展览」——一句话讲清机制，剩下的篇幅全给这件文物自己的理由。
- **这件自己的理由才是重点**：孤品、唯一带铭文、工艺失传、有机质易损、体量搬不动、历史上的劫难。
  挑一件最硬的说清楚，其余不提。
- 如果这件文物的「不能出国」实在没什么可说的（比如原因和其他同批文物完全一样），
  **就不写这一节**，在文章里带一句即可。

可用的事实（按需取用，别全抄）：

- 《中华人民共和国文物保护法》：国有文物、非国有文物中的珍贵文物不得出境；一级文物中的孤品和易损品禁止出境展览。
- 目录：2002 年首批 64 件（组）、2012 年第二批 37 件（组，书画类）、2013 年第三批 94 件（组），合计 195 件（组）。
- 审批：即便是普通一级文物出境展览，也要经国家文物局专项审批和限量管理，不是馆方能决定的。

## 信源与查证

- **优先信源**：本机的 `tools/relic_sources.py <文物名>` 能从 Obsidian 的原始材料抽出对应章节（169/195 件有）。那是 B 站 4 小时纪录片《如何快速认识195件禁止出境文物》的整理稿，**说话口语、细节丰富，但存在口误**——数字、年代、出土地点必须交叉核对，不能直接当结论。
- **需要联网查证**时，本机直连不通，**必须走代理**：`curl -x http://127.0.0.1:7890 ...`。维基百科接口可用：
  ```
  curl -sSG -m 60 -x http://127.0.0.1:7890 "https://zh.wikipedia.org/w/api.php" \
    --data-urlencode "action=query" --data-urlencode "prop=extracts" \
    --data-urlencode "explaintext=1" --data-urlencode "format=json" \
    --data-urlencode "redirects=1" --data-urlencode "titles=<条目名>"
  ```
- 博物馆官网、国家文物局、考古报告 > 百科 > 自媒体。
- 写不准的，用「据……记载」「学界一般认为」这类限定语，或者干脆不写。
